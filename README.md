# 词间 · WordFlow 1.4 — Kokoro 离线听读

中文界面的原生 Android 英语学习应用。使用内置 **Kokoro-82M 英语 INT8 模型 + sherpa-onnx 1.12.15** 在手机本地合成语音；不需要 API Key、联网、Google 服务或系统 TTS 语音包。

## 1.4 新界面及例句

- 首页显示词表卡片，点击进入单词列表，点开单词查看「导入例句」与「我的例句」。播放控制、语速、循环和缓存放在词表页面底部；返回首页时播放可继续。
- 每个单词可添加最多 20 条自定义例句，可编辑和删除；不会覆盖原 CSV 例句。数据原子写入，兼容已有词表。
- 播放 / 预缓存顺序：单词 → 非空导入例句 → 我的例句（添加顺序）。没有任何例句时只读单词，直接进入下一个。
- CSV 允许第二列为空，或只有第一列。单词仍不能为空，多于两列仍报告格式错误。

## 大模型生成例句与个人主页

右上角「个人」打开个人主页，可分别保存 DeepSeek / OpenRouter API Key，选择当前服务商。Key 输入默认隐藏，已保存的 Key 不回显；留空保留，独立清除按钮可移除。保存时通过 Android KeyStore AES-GCM 加密，不写入词表或导出源码。换手机后需要重新配置。

点开任意单词 →「使用大模型生成例句」。缺少 Key 时引导到个人设置。仅发送当前单词和例句生成提示到所选服务商，不发送整本词表。生成结果先显示在可编辑预览中，点击保存后才进入「我的例句」，不会自动覆盖导入内容。

- DeepSeek：固定调用 `https://api.deepseek.com/chat/completions`，模型 `deepseek-flash`，计费按账户规则。
- OpenRouter：调用 `https://openrouter.ai/api/v1/chat/completions`，默认模型 `openrouter/free`。该路由选择平台免费模型，仍需要用户自己的 Key，限额 / 可用性以平台为准；不会自动切换到收费模型。用户可手动填写其他模型 ID，可能产生费用。
- 只在点击时调用，不后台批量生成，不重试扣费请求；网络调用可取消，退出页面 / 息屏停止请求。取消客户端请求不保证服务商撤销已处理的计费。
- 只连接固定官方 HTTPS 域名，不跟随重定向传递 Key；设置连接和读取超时、响应大小上限，对认证、余额、限流等错误展示提示。
- 没有用户 Key，开发时没有调用收费服务或验证真实账户。已检查请求 / 响应协议；Android KeyStore 与真实服务连通仍需手机端验收。

官方说明：[DeepSeek](https://api-docs.deepseek.com/) · [OpenRouter 免费路由](https://openrouter.ai/openrouter/free/apps)。免费模型可用性会变动。

## 安装与使用

本次交付的 `/workspace/WordFlow-1.4-examples-ai-debug.apk` 支持 Android 8.0 及以上的 ARM64 / ARM32 手机。与交付的 1.0–1.3 使用相同签名，直接覆盖安装，不要先卸载，以保留词表。

1. 首次打开等待模型准备完成，界面会显示「Kokoro 离线英语」。模型解包到应用私有目录，之后打开直接复用。未升级缓存前已准备好的模型会复用。若使用预缓存词表，建议预留至少 1 GB 存储空间。
2. 点击「导入 CSV」，选择自己的单词与例句文件，或使用 `examples/daily-english.csv`。
3. 点击播放后按「单词 → 例句 → 下一单词」听读，支持暂停、继续、切词、循环及 0.5–1.5 倍语速。
4. 息屏或切到后台后继续播放；通知栏 / 锁屏提供暂停、继续、上一词、下一词等控制。

Kokoro 在手机 CPU 上进行推理。首次加载和每段语音的合成都需要时间，界面会显示合成状态；速度取决于设备。默认使用模型中的第 0 个英语声音（共 11 个声音，本版不提供声音切换）。本版内置英语模型，未打包多语言模型。

如果小米系统仍在锁屏后中断，可进入「应用信息 → 省电策略 / 电量与性能 → 无限制」。不同 MIUI / 澎湃 OS 的菜单名称略有不同。如需锁屏控制，请允许本应用显示通知和锁屏通知。

## 语音缓存（1.3 新增）

- **自动缓存**：首次正常播放并完整合成后，按文本、语速、声音和模型版本保存音频。重复播放或重开应用后命中缓存时，不再调用 Kokoro 推理，状态显示「正在播放缓存音频」。加载模型的启动时间仍然存在。
- **预缓存词表**：点击「预缓存词表」，按当前语速生成所有单词和例句，相同文本自动去重，已有有效缓存直接跳过。可息屏或切后台，通知栏显示进度并可取消。Android 13 及以上会在首次预缓存时申请通知权限，拒绝后仍可在应用内查看 / 取消。
- **缓存管理**：显示音频段数和占用空间，支持清理。清理只删合成音频，不删词表和内置模型。
- 完整缓存最多 **256 MB**。普通播放到达上限会淘汰较久未用的文件；批量预缓存到达上限会停止，保留已完成内容，避免把此前已生成的词条挤掉。
- 取消、切词、切表或调整语速时停止当前预缓存；已经完成的段落保留。再次预缓存会跳过它们。未完成的临时文件不会当成完整音频使用。
- 缓存带 CRC32 校验，损坏或截断的文件按未命中处理并重新生成；应用重开时清除异常退出遗留的临时文件。
- 音频位于应用缓存目录，系统清理应用缓存或空间不足时可能移除；届时正常播放会重新合成。模型与词表使用各自的私有目录，不受「清理语音缓存」影响。
- 预缓存不请求音频焦点，也不发声；正常播放会中止预缓存。Android 15 的后台 dataSync 时限到达时停止任务并保留已完成结果。

## 功能

- 每次导入创建独立词表，保存到应用私有目录；原 CSV 移动后仍可使用。支持切换和删除词表。
- CSV 支持 UTF-8 BOM、CRLF、可选表头、引号内的逗号 / 换行及双引号转义；整份文件验证并保存成功后才加入列表。
- 先读单词，再读对应例句，随后播放下一词；片段之间有 450ms 间隔，另有本地模型推理耗时。
- 暂停会立即停止当前音频，并取消旧合成结果；继续时重读当前片段。切词、切表和改语速后，过期回调不影响新播放。
- 长文本按句子及单词边界分成最多 240 个 UTF-16 单元的小段，限制单次合成和 PCM 内存占用。
- 前台媒体服务持有播放状态、Kokoro 模型及音频设备，与页面生命周期分离。播放期间按片段续期部分唤醒锁，暂停 / 结束 / 停止 / 服务销毁时释放。
- 耳机断开或失去音频焦点时暂停。通知中的停止操作会结束前台播放。
- 申请 INTERNET 权限用于用户主动调用大模型；本地 Kokoro 听读和缓存不需要联网。不申请麦克风和共享存储权限。CSV 通过系统文件选择器导入，模型随安装包提供。权限用于媒体播放前台服务、缓存的 dataSync 前台任务、唤醒锁，以及可选的通知进度显示。

## CSV 格式

请使用 UTF-8（Excel 可选「CSV UTF-8」）保存。第一列词汇（必填），第二列例句（可空）；也支持单列无表头的词汇文件。可直接放数据，也支持 `word,sentence`、`word,example`、`词汇,例句` 表头。

```csv
word,sentence
curious,I am curious about the world.
practice,"With practice, you will become more confident."
remember,"She said, ""Remember to take a break."""
```

包含逗号或换行的字段用双引号包围，内部的双引号写成两个双引号。忽略空行。单个文件最多 5 MB、10,000 条，每个字段最多 3,500 个 UTF-16 单元。

## 构建

需要 JDK 17 或以上、Android SDK Platform 35 和 Build Tools 35.0.0。仓库提供 Gradle wrapper 8.9，AGP 8.7.3。运行时依赖为固定版本的 sherpa-onnx AAR 和 Kotlin 标准库 2.1.0；应用自身仍使用 Java 17。

源码 ZIP 不重复打包大模型及 AAR。先下载固定版本的资源；脚本验证官方发行文件 SHA-256，模型下载包约 98 MB，AAR 约 37 MB。预装 APK 已包含这些文件，手机不执行此下载步骤。

```sh
python3 scripts/prepare-kokoro.py
./gradlew testDebugUnitTest lintDebug assembleDebug
```

SDK 路径可通过 `local.properties` 中的 `sdk.dir` 或 `ANDROID_HOME` 指定。产物：`app/build/outputs/apk/debug/app-debug.apk`。这是调试签名版本；本次提供的 APK 已用与旧版一致的调试密钥签名。其他机器自动生成的调试密钥不同，不能直接覆盖安装本次 APK，需使用原有密钥。

Android Studio 中先执行资源准备脚本，再打开本目录，使用项目自带 wrapper 同步并运行 `app`。GitHub Actions 配置也包含资源下载及测试 / lint / APK 构建步骤。

独立 CSV 检查：`bash scripts/check-csv.sh`。播放游标、文本分段、JNI 回调签名，以及缓存持久化、CRC 损坏、LRU 上限、取消临时写入和清理范围均由 JUnit 检查。

## 验证与设备验收

具体构建、校验及 Linux 推理测试记录见 `BUILD-VERIFICATION.md`。Linux 上成功合成音频，并使用实际 AAR 的 Java API 与应用同一 `KokoroCallback` 类测试 PCM 回调和取消生成。

尚未完成安卓模拟器、小米真机的音频及长期息屏验收。建议在设备上确认：

- 覆盖安装后保留词表，首次模型准备完成后，飞行模式下能播放单词和例句。
- 第一次正常播放保存缓存，重复播放 / 重开应用后显示命中；调整语速后合成独立音频。
- 预缓存时切后台 / 息屏仍有进度，取消后已完成内容保留，再次开始会跳过已有缓存。
- 拒绝通知权限后，仍可在应用内查看、取消和清理缓存；允许后通知中显示进度。
- 清理语音缓存不会删除词表 / 模型，缓存被系统清理后可正常重建。
- 连续播放、暂停续播、切词、快速切表、调整语速和循环正常。
- 息屏及切后台后持续播放多个条目，返回页面后位置和状态同步。
- 通知 / 锁屏控制生效，停止后通知移除；耳机断开或其他应用抢占音频时暂停。
- 长例句能完整播完，反复暂停 / 继续不会混播旧音频。
- 无效 CSV 导入失败时原词表保留，确认删除只移除所选词表。
